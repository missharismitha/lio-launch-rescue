# Plan: declutter Launch Control and stop exposing customer documents

Produced by the Plan agent, 21 Nov 2026. Build agents follow this document. Decisions are final unless a test proves them wrong.
Core approach: one filter layer `app/public.py` (allowlists) is the only thing that shapes API output for the browser. Raw snapshot, evidence and tool traces stay server-side for the agent. UI is rewritten around one decision; everything else lives in one Details drawer.

## A. Information architecture
First screen: slim top bar with ONE native `<select aria-label="Case">` (options "Game cards · 6,800 short" / "Magnets · check"; default game-card-shortage); one headline + one short sentence + one decision card; two edition lanes; a 3-step agent line; Plan B as up to 3 compact NON-clickable cards, only after the agent has run; a "Details →" link. Interactive elements besides the select: primary button and Details (max 4 allowed).
Details drawer (right sheet, full width at 390px, role=dialog aria-modal, Esc/scrim/X closes, focus returns to opener, hidden+inert when closed): Request (draft preview, name field, Approve, Send, notes), Why (numbers), Agent log (generic labels, "Run again"), "Check for new data", footer "Agent {ready|not set up} · Portal {live|offline}".
REMOVED: ask box, "other risks" section (switcher covers it), "Where this comes from" and every Open link, 4-number equation as a section, long lede, fact chips, portal/AI pills, agent "What I verified"/"Contradictions", supplier-language message.

## C. Backend / privacy changes
New `app/labels.py`: `step_label(name,args)` returns ONLY generic labels, never argument text. Tools: Read, read_document, Grep, Glob, search_documents, get_current_issue. Path hints: supplier/notice/advice -> "Read a supplier notice"; contract -> "Checked a supplier contract"; polic/approval -> "Checked the approval policy"; erp/stock/receipt -> "Checked stock records"; plan/status -> "Checked the packing plan"; else "Read a source document". Grep/Glob/search -> "Searched the records". get_current_issue -> "Reviewed the stock numbers". `GENERIC` = set of allowed labels (include "Checked a record").
New `app/public.py`:
- `scrub(text, limit=None)`: strip backticks; drop any sentence containing a file-like token (regex `[\w./\\-]+\.(pdf|csv|xlsx|docx|png|jpe?g|md|txt|eml)\b` or a path with `/` plus known folder); drop quoted spans of >=4 words (straight and curly quotes); truncate at word boundary.
- `public_investigation(inv)` -> `{verdict, action, options:[{title,detail}] (max 3), at}` or None. verdict from `## Verdict` <=160 chars; action from `## Recommended action` (fallback legacy regex "Recommended next action:") <=200; options from `## Plan B options` bullets `**Title** — sentence`, title <=40, detail <=90. Never return text, tool_calls, model. Everything through scrub. Robust to missing sections (never crash; empty options).
- `public_events(events)`: keep kinds drafted, approved, sent, investigated, agent_tool, delivery_unknown, offer_reviewed; message replaced from fixed map (drafted "Request drafted", approved "Approved", sent "Sent", investigated "Agent finished", delivery_unknown "Delivery not confirmed. Check sent mail.", offer_reviewed "Offer reviewed"); agent_tool kept only if message (minus "Agent: ") is in labels.GENERIC else "Checked a record".
- `public_overview(raw)` allowlist: launch_date, analyzed_at; products [id,name,target,packed,remaining,hours_needed,hours_available]; pack_status only hours_left, as_of; issues [{id,title,shortage}]; agent {running,state,steps,error,last_run} with each step message scrubbed/mapped via GENERIC (messages starting "Agent:" or a tool name -> GENERIC); integrations booleans portal_enabled, ai_enabled, email_enabled; sync {last_success, error: bool}; case_versions. Drop warnings, inbox. Builder: dump the real overview once and confirm no other leaking keys.
- `public_detail(detail)` allowlist: id,title,shortage,required,usable_stock,incoming; supplier {name}; shipments [{ordered,shipped,balance,balance_eta}] (no po_number/reference); allocation {lines:[{product_id,name,short}]} (no rule); case {state, approver, sent_at, delivery_status, approved: bool (approved_fingerprint == source_fingerprint), draft {subject, body, has_recipient} (no `to`), investigation: public_investigation(...), source_fingerprint, approved_fingerprint}; events: public_events; integrations booleans; replies reduced to {id, received_at, source_fingerprint} (check test_reply_loop for needed fields; never body/from/subject); chat with text scrubbed. MUST NOT contain keys evidence, path, excerpt, sha256, tool_calls, text, model, summary, actions, recovery.
New `app/access.py`: `enabled()` reads LIO_ACCESS_CODE at call time; key=sha256('lio-session|'+code); `make_cookie(now)` -> f"{exp}.{hmac_hex}" 12h expiry; `valid_cookie` checks expiry + hmac.compare_digest; `check_code` compares sha256 digests with compare_digest (length-safe); rate limit per client IP 5 failures/5 min plus global 30 failures/10 min; 429 without checking code when limited; success clears IP failures; clock via module function `_now()` (patchable). `LOGIN_HTML` inline page: form + password input + `<link href=/static/styles.css>` + `<script src=/static/login.js defer>` (no inline script). `PUBLIC={'/login','/api/login','/api/health','/static/styles.css','/static/login.js'}`.
`app/main.py`:
1. Single middleware `boundary` replacing `local_boundary`: (i) if access.enabled() and path not in PUBLIC and no valid cookie: /api/* -> 401 {'detail':'Access code required'}, others -> 303 to /login; (ii) existing cross-origin check on non-GET; (iii) call_next; (iv) apply headers to EVERY response incl. early returns: X-Content-Type-Options nosniff, X-Frame-Options DENY, Referrer-Policy no-referrer, Permissions-Policy camera=(), microphone=(), geolocation=(), Content-Security-Policy "default-src 'self'; style-src 'self' 'unsafe-inline'; script-src 'self'; frame-ancestors 'none'; base-uri 'none'; form-action 'self'", Cache-Control no-store.
2. Routes: GET /login (LOGIN_HTML, or redirect to / if cookie valid or no code set); POST /api/login {code} -> 200 + cookie `lio_session` HttpOnly SameSite=Strict Path=/ Max-Age=43200, Secure when https / X-Forwarded-Proto https / env LIO_COOKIE_SECURE=true; 401 wrong; 429 limited; POST /api/logout clears cookie.
3. TrustedHost allowed_hosts also includes comma-separated env LIO_ALLOWED_HOSTS. Document `--proxy-headers --forwarded-allow-ips='*'` behind TLS proxy.
4. Public projection at EVERY route boundary: overview, refresh, /api/sync return public_overview(overview()); get_issue and draft, investigate, approve, send, replies/import, replies/review, chat return public_detail(issue_detail(...)). Internal callers (agent_cycle, send guards) keep raw issue_detail.
5. /api/evidence: first line `if os.getenv('LIO_EXPOSE_SOURCES','').lower() != 'true': raise HTTPException(404,'Not found')`; rest unchanged (still behind access gate).
6. investigate() progress callback records only generic labels (no tool-name prefix).
7. chat_message: `answer = public.scrub(answer)` before store.chat_turn.
8. Startup: log one warning if LIO_ACCESS_CODE unset and host not loopback.
`app/investigator.py`: `describe_call` returns labels.step_label(name,args) (trace list stays raw server-side). Prompt headings in order: `## Verdict`; `## Recommended action` (one sentence); `## Plan B options` (max 3 bullets `**Short title** — one plain sentence, no jargon`); `## What I verified` (file citations allowed here only, never shown in UI); `## Contradictions and unknowns`; `## Message to supplier`; `## Needs human approval`. Add: "In Verdict, Recommended action and Plan B options never mention file names, paths or document quotes."
`app/claude_agent.py`: same SYSTEM prompt change; `progress(labels.step_label(name, block['input']))`.
`app/chat.py`: sources branch returns "Source documents stay on the server and are not shown here. Ask the customer's team if you need the original." (no labels/excerpts); remove "Open Evidence in the inspector…".

## G. Risks and acceptance
Risks: allowlist drift (intended; recursive test guards); agent output may omit sections -> fall back, never crash; over-aggressive scrub must not leave empty boxes (use fallback copy); old stored investigations/events may contain file names -> cleaned on output, no migration; behind a proxy client IP is the proxy so the global limiter is the real defence; document HTTPS-only hosting; limiter and agent status are in-memory (single worker OK); draft body (with PO/waybill) is shown to the approver in the drawer by design; poll re-render must not close drawer or drop typed name.
Acceptance: (1) all tests pass + `node --check` on app.js and login.js; (2) /api/evidence 404 by default incl. real file; 200 only with LIO_EXPOSE_SOURCES=true (and valid cookie if code set); (3) no file name or path in rendered DOM text, drawer text, /api/overview, /api/issues/{id} or any POST response (regex `\.(pdf|csv|xlsx|docx|png|jpe?g|md|txt|eml)\b` and path fragments); (4) first screen <=4 interactive elements besides the select (expected 2); (5) first-screen visible copy <=~120 words; (6) no jargon; (7) no horizontal scroll at 390px incl. drawer open; (8) every case in the select shows a headline and decision state; (9) approval flow works locally, Send disabled without sender, stale-source guard still invalidates approval; (10) with LIO_ACCESS_CODE set: redirect to /login, wrong code fails, right code opens, cookie HttpOnly SameSite=Strict, 5 bad tries -> 429; (11) headers on /, /login, /api/*; (12) README and docs/STATUS.md updated with new env vars (LIO_ACCESS_CODE, LIO_EXPOSE_SOURCES (default off, local debugging only), LIO_ALLOWED_HOSTS, LIO_COOKIE_SECURE) and the privacy rule: the browser never receives source documents, file names, paths or excerpts.
Assumptions: supplier draft may be shown in the drawer for approval; public hosting is behind an HTTPS proxy.
