# Plan: agent crew, decision brief, what-if, UI upgrade (beat Lio's agents in the launch-crisis niche)

Produced by the Plan agent after researching Lio's public material (lio.ai, a16z, TechCrunch, YC). Facts: Lio sells a "virtual procurement workforce" of many specialised agents running in parallel ("Agent Operating Procedures", "Lio OS"), 175+ enterprise customers, ERP/inbox/Teams integrations, steady-state high-volume procurement. UI, approval model and any time-boxed crisis mode are NOT public (unknown). Do not claim breadth; our wedge: Launch Control room for the 30 hours when one launch breaks: time-boxed, packing-line aware, allocation aware, policy aware, every number recomputed in code, human-in-the-loop by design, output hand-off-able to Lio-style agents. Pitch lines: (1) Lio's agents run procurement end to end for 175+ enterprises; Launch Control is the room you walk into when one launch is 30 hours from failing. (2) It reads the same messy sources, then answers with a priced option, the person who must approve it, and the copies it saves, each number recomputed in code. (3) Human-in-the-loop by design: it drafts and routes, the right approver decides, and it hands its output to agents Lio already runs.

Constraints (AGENTS.md + docs/PLAN_UI_PRIVACY.md): customer files private; the browser never sees documents, file names, paths or quotes: everything user-visible goes through app/public.py allowlists + scrub; approval before any external email or spend; send disabled without a registered sender (user approved ONE real inquiry to Hwaseong later, only after named approval of exact text); supplier drafts contain only supplier-facing facts; no real email/OpenAI/claude CLI calls in tests; no hardcoded business numbers. Modules app/policy.py, app/pricing.py, app/value.py are built by another agent (API: policy.required_approver, pricing.price_option/rank_options, value.value_at_stake/contract_claim); wire through them, do not edit them.

## Agent upgrades (ranked)
1. Crew with shared state and hand-off trace (app/crew.py, ~1.5 h). Blackboard dict (issue, hours_left, options, priced, approver, drafts, checks) passed through deterministic role functions; each role appends trace entries {agent, action, outcome, at, autonomy}. Roles: Reconciler (engine numbers), Investigator (existing LLM loop, wrapped; proposes option SHAPES: title, quantity, mode, eta), Allocation Planner (recovery/packing math), Pricer (pricing.py), Policy Officer (policy.py), Approver-Router, Drafter (supplier draft + internal escalation draft). A role failure degrades to the next role and is traced. Hook: app/main.py agent_cycle calls crew.run(issue_id). Autonomy ladder table in crew.py: read/compute/draft = auto; send/spend = needs approval; book/pay = never.
2. Number self-check (app/verify.py, ~1 h): drafts are built from a template with numbers injected by code; every number/date extracted from any draft or LLM text is recomputed from the blackboard and must match, else reject, retry once, then template fallback; expose `numbers_verified: bool`.
3. Scenario what-if (app/whatif.py, ~1.5 h): pure function over recovery.packing_hours math: ships(arrive_at) -> copies of the short edition that still ship, Collector's first; boundaries: arrival at/before now, within hours left, after the last packing hour. Route POST /api/issues/{id}/whatif {arrive_at_hours or iso} (hook in main.py; response through public allowlist, numbers only).
4. Decision brief (app/brief.py, ~1 h): recommendation, price, approver, copies gained, deadline, confidence (low|medium|high), risks, "what I'd verify next"[]. Added to public detail as `brief`.
5. Confidence and contradictions (app/conflicts.py, ~1 h): ERP stock vs delivery note vs tracker; CPO memo vs plan; output {field, sources_disagree, chosen, why, confidence} naming sources by CATEGORY only (never file names).
6. New-drop diff with code-composed reason (app/diffs.py + runs.py, later wave).
7. Fallback/robustness (app/fallback.py, runs cache, health strip, later wave).
Cut if short of time: release gate (ECN sleeve), reply triage, second-customer fixture.

## Public JSON additions (contract between backend and UI; allowlisted in app/public.py; plain English, no file names)
detail.options[]: {title, detail, price_eur|null, eta|null (e.g. "Sun 02:00"), copies_gained|null, approver:{role, vacancy:boolean}|null, feasible:'yes'|'late'|'unknown'}
detail.brief: {recommendation, price_eur|null, approver:{role,name|null,vacancy}, copies_gained|null, deadline, confidence, verify_next:[strings]}
detail.value: {headline_eur|null, basis:'cost'|'revenue', label, claim_eur|null}
detail.trace[]: {agent, action, outcome, autonomy:'auto'|'draft'|'approval'|'never'} (fixed vocabulary, scrubbed)
detail.escalation: {to_role, subject, body, approved:boolean}|null (internal draft, named approval, never auto-sent)
detail.numbers_verified: boolean; detail.conflicts[]: {field, why, confidence}
POST /api/issues/{id}/whatif -> {arrive_label, copies_ship, copies_short, hours_left}

## UI upgrade (UI agent; consumes only the public JSON; keep dispatch-board identity)
First screen (<=4 interactive controls at 390px: Approve, what-if slider (text input fallback), Details, Run again; ~120 words):
headline; one money line "About EUR {x} of product cost short" (caption "cost basis, not price") plus "Fix costs EUR {y}" when known; decision card: "Recommend: {brief.recommendation}. {price}", "Approver: {role} ({vacancy note})", confidence chip, primary button "Approve and draft both messages" with subtext "Nothing is sent until you confirm the supplier email."; edition lanes; what-if slider line "If cards arrive {time}: {n} Standard copies ship"; "Since last run" strip (only when diffs exist); agent line with named roles; Plan B cards with price, ETA, copies gained, approver chip and feasibility chip (unknown price shows "unknown", never a guess).
Drawer sections in order: Decision brief, Agent timeline (one line per role with autonomy chip and outcome, no file names), Numbers (+ numbers-verified badge), Drafts (supplier request + internal escalation with named approval), Health.
Copy: empty "Waiting for Soony's data."; loading "Agents at work: {role}"; error "Model unavailable. Showing the {HH:MM} result and the rule-based plan."; strip "Since last run: {n} changes. {reason}".
Tokens: ink #0e1114, amber #ffb703, positive #52c48a, risk #ff6b5b, text #e7e9ec; Bahnschrift/DIN/system stack; tabular numbers; radius 6px; hit targets >=44px. Motion only to explain state (step dot pulse, what-if number tween 200ms, strip slide-in once), all honouring prefers-reduced-motion. Accessibility: aria-live polite on agent line, visible amber focus ring, never colour alone, contrast >=4.5:1, drawer focus trap and return. Only append new rules to styles.css where possible (no rewrite).
