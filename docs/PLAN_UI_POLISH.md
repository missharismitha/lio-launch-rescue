# Plan: Launch Control UI polish (research-backed; no third-party code needed)

Produced by the Plan agent after reading: anthropics/skills frontend-design (rules: type scale, 4-6 named colours, boldness in ONE element, one orchestrated motion moment, copy is design; anti-patterns: eyebrow labels, middle-dot meta strings, "WORD — fragment" labels, monospace for small labels, arrows on links, gradient washes, identical rounded cards, big-number/small-label tiles, 01/02/03 markers on non-sequences), pbakaus/impeccable (Apache-2.0; critique/audit/polish commands), nextlevelbuilder/ui-ux-pro-max-skill (MIT; checklist only), Vercel web-interface-guidelines (tabular-nums, animate only transform/opacity, never `transition: all`, :focus-visible, aria-live polite, touch-action: manipulation, overscroll-behavior: contain, destructive actions need confirm), plus shadcn/Radix/assistant-ui/AI Elements/Tremor/Open Props/Lucide (patterns only). Skip any CDN font/CSS, React kits, chart/Gantt libs. Licence of anything copied must be re-confirmed from the repo; only Lucide icon paths (ISC) may be copied, into an inline <symbol> sprite with app/static/vendor/LICENSE-lucide.txt.
Hard constraints: vanilla HTML/CSS/JS, no build, CSP default-src 'self'; style-src 'self' 'unsafe-inline'; script-src 'self'; no external network assets; browser never sees documents/file names/paths/quotes/emails (textContent only, never innerHTML); first screen <=4 interactive controls and ~120 visible words at 390 px; prefers-reduced-motion respected; AA contrast; keyboard + screen reader support. UI agent owns ONLY app/static/index.html, styles.css, app.js, new app/static/print.css and app/static/vendor/LICENSE-lucide.txt; NO backend edits. Append/migrate component by component rather than a blind rewrite; keep existing behaviour (approval gate, polling, drawer focus handling, access-login redirect on 401).

## Design system
Hybrid theme: near-black board band (top bar + headline) over cool paper body; `color-scheme: light`; a print.css for the one-page brief. Amber used ONLY for the primary action, focus rings and the "now" marker; risk red, ok green, nothing else saturated. Type: Bahnschrift > Segoe UI Variable > system-ui, weights 400/600/700 only, tabular-nums on all numerals (NOT monospace for labels; mono only inside draft text), headline clamp(28px,4.2vw,44px)/1.1/600, body 16/1.5, line length <=62ch, `text-wrap: balance` on headings and `pretty` on paragraphs, `&nbsp;` between number and unit.
Tokens (append as :root, keep old variables as aliases; give every oklch colour an sRGB hex fallback declared first, override inside @supports (color: oklch(0 0 0)); measure contrast in the browser before shipping): ink/ink-2/ink-3, paper, card, line, board/board-2/board-text, amber/amber-ink, ok/ok-bg, risk/risk-bg, warn/warn-bg; spacing 4/8/12/16/24/32/48; radii chips 6, cards 10, decision card and drawer 16; type scale 13/15/17/22/clamp headline; shadows sh-1, sh-3; durations 120/220/420 ms; ease cubic-bezier(.2,.7,.2,1). Starting values: --ink oklch(.2 .01 255); --ink-2 oklch(.42 .015 255); --ink-3 oklch(.5 .015 255); --paper oklch(.965 .004 250); --line oklch(.89 .006 250); --board oklch(.19 .01 255); --amber oklch(.82 .17 80); --amber-ink oklch(.28 .06 80); --ok oklch(.5 .11 160); --risk oklch(.5 .17 28); --warn oklch(.5 .11 65).

## Components
1. Headline band: board background, H1 "{n} {Edition} copies won't ship on time." (number bold amber), one countdown line "Trucks leave {Sun 22 Nov 20:00}. {h} h of packing left." (date from data, hours from pack_status.hours_left), a segmented hours bar (role=img, aria-label "{h} of {total} packing hours left", cells via CSS grid).
2. Decision card: white, radius 16, shadow sh-3, 6px amber left rule, <dl> for "Fix costs", "Approver" (chip), "Copies gained"/ETA, amber button "Approve and draft both messages", note "Nothing is sent until you confirm the supplier email." No eyebrow label. States: idle, running, drafted, approved, sending/delivery_unknown ("Delivery not confirmed. Check sent mail.", no button), sent, error (calm warn rule "Model unavailable. Showing the {HH:MM} result and the rule-based plan.").
3. Packing-line strip (signature element): per edition a track of three segments: packed (ink), will ship if parts arrive (green), short (risk red with diagonal hatch pattern); status also as text ("6,800 short"), never colour alone. What-if: native <input type=range> (accent-color amber) "Parts arrive", step 1 h, PageUp/PageDown 6 h, Home/End; live <output> "If cards arrive {label}, {n} Standard copies ship."; POST /api/issues/{id}/whatif {arrive_in_hours} debounced 120 ms, abort the previous request; text-input fallback in the drawer; aria-valuetext.
4. Option cards "boarding pass" stubs (not the same card as lanes): left chamber price + title, right chamber ETA, copies gained, approver chip, feasibility chip yes/late/unknown; first marked Recommended; unknown price = hatched chip "unknown"; container-type: inline-size so they work in page and drawer. On 1280 show up to 3 stubs under the lanes; on 390 only in the drawer.
5. Agent rail: <ol> of the roles (Reconciler, Investigator, Allocation Planner, Pricer, Policy Officer, Approver-Router, Drafter, Checker) each with dot, name, outcome, autonomy badge (auto/draft/approval/never as text+icon); first screen shows only one line "8 agents checked. 2 need your approval."; full rail in the drawer (vertical at 390, horizontal scroll-snap inside its own container only).
6. Chips: dot + text, variants ok/risk/warn/neutral; buttons >=44 px, touch-action: manipulation, no arrows in labels, press state translateY(1px), disabled has an explanation line.
7. Drawer: native <dialog> showModal() with ::backdrop (focus trap/Esc/inert for free), slide via @starting-style + transition allow-discrete (Chrome; no animation fallback), full width at 390, overscroll-behavior: contain. Sections in order: Decision brief (recommendation, price, approver, confidence chip, "What I'd verify next" list, Print one-page brief button), Agent rail, Numbers (+ "Numbers verified" badge and conflicts), Drafts (supplier request + internal escalation, approver name field prefilled from approver.name when known, TWO-step approval: amber button opens approval panel, then "Confirm as {name}"; NO hold-to-approve), Cases + Run again + Check for new data, Health footer ("Agent ready, Portal live").
8. Toast role=status (translateY+opacity 180 ms, 5 s, pause on hover/focus); skeleton shaped like the decision card (shimmer on background-position, shown only after 300 ms, static under reduced motion); empty "Waiting for Soony's data."; error as above.
9. Icons: ONE inline SVG sprite (<symbol>) at end of body, ~8 icons (clock, truck, shield-check, user-check, file-text, printer, x, chevron), used via <svg class="ic" aria-hidden="true"><use href="#i-clock"/></svg>; no icon font.
Native techniques to use: <dialog>, color-mix() for chip tints, oklch, :has(), CSS nesting, container queries, text-wrap, @starting-style, scroll-snap; optional Chrome-only with fallback: View Transitions (`document.startViewTransition?.()`), @property count-up. Skip: anchor positioning, scroll-driven animations, subgrid, light-dark().

## Motion (only what explains state; all off/instant under prefers-reduced-motion)
Hours bar fills once on load (420 ms); what-if number and lane segments 120-200 ms; running agent dot pulses 1.2 s loop only while running; "since last run" strip slides in once (220 ms); drawer slide 220 ms; approve confirmation swaps text to "Approved by {name}" with a check drawing in (300 ms); skeleton shimmer 1.4 s. No hover transitions on cards, no slide-up on every section, no sound, never `transition: all`; animate only transform/opacity.

## Verification checklist (browser pane or Chrome)
1280 and 390: scrollWidth <= innerWidth; 4 focusable controls and ~120 words on the first screen at 390; contrast >=4.5:1 text and >=3:1 non-text (measure, incl. track segments and amber states); keyboard-only full flow incl. approval with visible focus, Esc closes drawer and focus returns; prefers-reduced-motion emulated (no looping animation); no console errors; no CSP violations (no inline script, no external URLs); only same-origin requests; DOM text has no ".pdf", ".csv", "/data", "soony/", "@"; offline reload works; print preview of brief fits one page; slow-network skeleton and API-error state; 200% text zoom works.
Risks: backend fields not ready (degrade gracefully); first-screen word/control creep; oklch values missing AA (keep sRGB fallbacks, verify); @starting-style/allow-discrete Chrome-only (accept no animation); what-if stale values (abort previous requests); dialog focus return when the opener re-renders (re-find opener by id); amber overuse (3 roles only).
Dev-time skills (the lead may install; review each SKILL.md first): `/plugin marketplace add pbakaus/impeccable` (Apache-2.0; run /critique and /audit on the finished page); `/plugin marketplace add anthropics/skills` (frontend-design); optional `npx skills add vercel-labs/agent-skills --skill web-design-guidelines`.
Pitch (3 sentences): Launch Control looks like a dispatch board because that is the job: a near-black band, one signal-amber action, tabular numbers, and a packing-line strip you can drag to see the shortfall change. One screen, one recommendation, one named approver and one click, everything else in a single drawer, and a one-page brief to print for the CPO. We kept it plain on purpose: no CDN, no external fonts, no icon fonts, honest "unknown" states, motion only where it explains a change, so it is fast, private and calm at 20:00 on a Sunday.
